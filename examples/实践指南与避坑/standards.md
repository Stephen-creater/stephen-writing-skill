# 实践指南与避坑

## 适用

团队实践、工作流、治理机制、最佳实践和避坑指南。

## 写法

- 文章由具体产品或官方实践触发时，标题直接写明对象和读者能获得的价值，第一节解释它带来了什么变化。
- 可以用编号组织，但来源中的经验数量不决定正文结构。只保留能组成当前主线的原则，其余整条删除。
- 两条原则存在直接依赖时合并讲。例如 Agent 先看见团队上下文，再在共享空间里明确分工。
- 每一点都要有明确结论，并说清原因、案例或操作方法。一个案例已经证明判断时，不再追加同类案例。
- 把经验落到可查对的机制：输入输出、触发条件、权限、共享空间、角色、目标、Owner 和测试。
- 具体数字只在有经验或证据时使用，不用精确数字制造专业感。
- 结尾回到组织、业务或用户最终会发生什么，不复述前面的步骤。

## 避免

- 只给原则，没有可执行做法。
- 把特定公司的情况写成所有团队的统一规则。
- 用工具名、文件夹和专业词数量代替真正治理。
- 为了显得完整，把官方原文中的每一条经验都保留下来。
- 删掉产品、发布或事件本身，只剩一篇脱离时间背景的通用方法论。
