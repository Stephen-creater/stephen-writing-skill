# 实践指南与避坑

读者想知道：到了某个要做决定或要动手的时候，该检查什么、怎么做、做到什么程度算过关。

## 常见写法

- **一个流程**：原理 → 输入 → 处理 → 产出 → 以后怎么复用。
- **几条标准共同决定一件事**：「4 笔账」「3 个问题」，每条都缺一不可。
- **团队做法**：现实发生了什么变化 → 团队怎么配合 → 能照做的动作 → 质量怎么保证。

## 容易出错的地方

- 标题要写清对象、动作或决定的时刻，不要把所有企业 AI 问题装进一篇。
- 流程里的文件、字段按实际出现的顺序讲，后一步的东西不提前展开。
- 标题的数字、小节、判断项、结尾问题一一对应，不为凑数留一条。
- 每条标准只用一个主要案例，案例只证明这一条。
- 团队项目只留证明方法有效的人数、周期、场景、过程和成果；履历、服务介绍、招募入口删掉。
- 每条原则至少落到原因、动作、验收中的两样，不能只喊口号。
