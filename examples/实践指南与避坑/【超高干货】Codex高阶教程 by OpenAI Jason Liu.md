# 【超高干货】Codex高阶教程 by OpenAI Jason Liu

OpenAI 开发者体验工程师 Jason Liu 在 75 分钟工作坊里，完整演示了他如何用 Codex 管理语音输入、Skills、长线程、记忆库和自动化任务。

## compaction让long history session可行了

compaction（上下文压缩）已经好到可以依赖。半年前，很多人建议对话超过二十条就新开线程。Jason 现在有一个线程已经运行五周，其间调度过四百个子代理，依然知道自己在做什么。

这意味着，线程可以从用完即弃的对话，变成持续管理项目的工作单元。

他会把项目线程钉在侧边栏，用项目 ID 重命名，再让它调度子代理、记录进展并定时唤醒自己。

## 语音输入：三倍于打字的表达速度

Jason 有个玩笑，钢铁侠不会给 Jarvis 打字。他用一个键转写、一个键回车，说完任务就继续工作。

说话速度大约是打字的三倍。语音还允许你把没有整理过的想法直接交给 AI，再让它从会议、邮件和文档中找到线索，组织成完整产物。

他曾输入一段十五分钟的语音，只记得上周和 Charlie 聊过 Agents SDK。Codex 从三十五条会议记录里找到对应内容，再整理成文档。

## Appshots：截图加上无障碍树的完整上下文

普通截图只有画面，模型还要做 OCR、查频道和用户信息。Appshot 会同时抓取应用的无障碍树，因此能直接拿到 Slack 频道 ID 和成员 ID。

你只需要说「调研后回复」，Codex 就能把消息发到正确频道，并 @ 正确的人。

## 技能与插件生态：从用到造

Skill 是一组指令、参考文件和脚本，Plugin 则把多个 Skill 打包在一起。经常重复的做法可以封装成 Skill，多个 Skill 再组成可安装的 Plugin。

Codex 已经有官方 Skill installer 和社区技能库，也能从侧边栏直接安装 Slack、Gmail 和 Teams 等连接器。

对团队来说，最有价值的做法是找出反复出现的工作，把流程、规则和异常处理固化成共享 Skill。

## 自我改进的技能与「像我一样写作」

Jason 做完一件事后，会让 Codex 把过程固化成 Skill，并允许 Skill 在使用中修改自己。出错就纠正，下次运行时直接使用新规则。

个人 Skill 可以边用边改，需要共享给团队的 Skill，则要先经过更长时间的真实使用。

他的 `write like me` Skill 会读取过去六个月的邮件和 Slack 消息，生成语言风格指南。之后起草内容时，它会根据客户工单或同事沟通自动调整语气。

## 个人 monorepo：记忆库的目录结构

Jason 的个人 monorepo 用文件系统保存长期记忆。`projects/` 里是每个项目的进展，`people/` 里是相关人员的背景和正在思考的问题。它遇到新联系人或新项目时，会自动建立档案。

他在 `AGENTS.md` 里规定，代码统一放到 `/dev`，不能存进记忆库。每个项目再用自己的 `AGENTS.md` 限定工具和规则，避免记忆串到其他项目。

整个记忆库同时是一个 Git 仓库。过几天运行一次 `git diff`，就能看清 Codex 更新了什么，哪些任务还没有闭环。

## heartbeat+loop：定时唤醒thread+跟进

heartbeat（心跳）会定时向原线程发送消息。比如「每三十分钟检查一次」，线程就会带着原有上下文继续工作，无需每次新建对话。

monorepo 里的 loop Skill 会用这个机制持续跟进任务。比如盯住一个 PR，有反馈就修改，同步主分支，并始终保持 CI 通过。

## 幕僚长线程：个人工作的单一事实来源

幕僚长线程是 Jason 个人电脑上一切工作的单一事实来源。它每天早上八点被唤醒，检查所有连接器，然后把需要人处理的事集中到一处。

Jason 让每封邮件和 Slack 消息都带上原文链接，便于直接打开、审阅和回复。同一线程还会每周整理 OpenAI 的发布计划，把时间、延迟和负责人汇总成简报。

有段时间，幕僚长线程还会为每封待回复邮件打开一个 Chrome 页面。Jason 开完会回来，只需要逐条审阅和发送。

## Goal：只要验证没通过，就继续执行

`/goal` 会先定义一个验证条件。只要验证没通过，线程就继续工作。Jason 曾让它把 Python 项目迁移到 Rust，直到全部测试通过。

Ultra Goal 把目标放进 `goal.md`，把运行记录放进 `state.md`。你可以在任务运行时修改目标，也可以直接读取日志，不必回看几 GB 的会话记录。

如果你不会写完整的 Goal，可以先说一段语音，让模型自己整理目标和验证条件。人只需要决定它应该变成 Goal、新线程还是新 Skill。

## Computer Use：让Codex直接操作电脑

Computer Use 是 Jason 久违地在工作里感受到 AGI 的时刻。他第一次使用 iMovie 时，Codex 直接操作软件，完成导出影片、寻找音效和对齐时间戳。

Chrome 扩展只控制浏览器，Computer Use 可以在后台操作任意应用。打开 locked use 后，电脑合盖且连接电源时，你仍然可以通过手机发起任务。

这些操作不会一直抢占屏幕。Jason 曾看到 Codex 在后台打开三个标签页，处理完 Twitter 私信后又自行关闭。

## Artifacts：文档也能成为可操作的工件

Codex 可以直接打开和渲染 Excel、Word、PDF 和幻灯片，再根据标注修改。Jason 这场演讲的幻灯片，就是边讲边让 Codex 生成和修订的。

## 监视线程：让一个线程调度其他线程

监视线程会持续寻找问题。发现新故障时，它会创建一个分诊线程去处理。同一故障再次出现时，它会通知已有线程，同时提醒人介入。

如果故障持续三天没有解决，主线程才会把它推到人面前。人不必盯着每个处理步骤，只需要接管异常。

子代理藏在后台，钉住的线程则会出现在侧边栏。因此，侧边栏可以成为所有进行中工作流的中枢。

线程控制也不需要记工具名。你可以直接要求 Codex 找到某个旧线程、重命名、钉住，或者让一个线程去唤醒另一个线程。

## 品味：先大量体验，才能准确判断

Jason 认为，想有好品味，首先得先吃。你需要使用足够多的应用，感受好的引导流程，也亲自遇到令人烦躁的设计，才能建立描述问题的词汇。

这和做饭一样。不认识食材，就说不出一道菜究竟是太咸，还是缺少酸味。

模型可以生成一切，人仍然需要判断什么值得保留。

## 理智用Token：多数任务不需要X-high

X-high 只代表模型思考得更多，不代表结果一定更好。Jason 的幕僚长线程默认只用 medium，日常任务使用 low 或 medium 已经足够。

航班值机、下载登机牌这类步骤固定的任务，使用低推理档位就能完成。

自动化任务还要控制唤醒频率和停止条件。没有新进展时，只让线程返回一个词，就能避免无意义地消耗 token。
