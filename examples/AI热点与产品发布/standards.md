# AI 热点与产品发布

## 读者任务

让读者判断这次变化与自己的工作有什么关系，值得怎么试、怎么选；发布事实提供判断所需的背景。

## 实践判断优先

模型升级、工具更新等面向日课读者的产品文章，默认从作者与读者的实际任务出发。正文需要呈现证据支持的作者判断和具体使用建议；仅说明发布了什么、罗列功能和媒体评价，即使准确，也没有完成这类文章的任务。

- 动笔前确定一个受影响的工作问题，以及读者读完会改变的选择或动作。先据此选材料，再安排能力、入口和价格；不把公告目录直接当文章主线。
- 有作者真实测试时，交代做了什么、返回什么、哪些结果支持判断。没有亲测时，优先只选一篇署名文章中的一个完整案例，保留第三方归属，沿着输入、结果和判断写完，不拼接多位作者或多个同类案例。短篇产品日课依赖图片证明案例时，通常只保留 1 至 2 张，优先用输入与输出闭合证据链；教程和操作指南不机械套用这一数量。
- 判断要改变取舍，建议要能执行。说明谁适合先试、怎样试、按什么结果决定采用或保留旧流程。无需把这些问题机械拆成固定章节，也不要只在结尾补一句泛泛建议。
- 第一人称用于承担判断和选择。删去「我觉得」「我建议」后，如果剩下的仍然只是功能清单，应重做选材和结构。覆盖率达标不能代替这一检查。

适用边界：用户明确要求新闻快讯、客观公告、入口价格查询或纯功能速览时，按所需信息组织，可以使用导航结构；不强加亲测叙事和个人观点。导航标题也可服务实践判断，是否合格取决于内容能否帮助读者选择与行动。

## 常用路径

- 产品日课：工作问题 → 使用证据 → 作者判断与行动建议。
- 单功能热点：发现对象 → 官方定义 → 使用场景 → 核心判断 → 隐私或边界。
- 产品速览：入口 → 核心能力 → 功能地图 → 生态 → 价格。
- 协议或标准：是什么 → 怎么工作 → 当前开放范围与限制。

只选一种主路径。千字短文可以不用小标题；速览可以用导航型小标题，不强制下观点。

## 本类独有检查

- 标题或第一节明确发布对象和现实时间点。
- 参数、Demo 和竞品只在改变使用或判断时保留。
- 测试或对比只在支持当前判断时保留；标题没写「实测」不等于应删除有用的使用证据，也不能借此扩成完整评测。
- 官方 Demo 只重演机制时删除。定义、机制和边界完整后，仍须检查是否完成了本次读者任务。
- 行业发布可以点名直接竞品，但格局推演不能替代产品日课应有的实践判断。
