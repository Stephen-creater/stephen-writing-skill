很多人听到知识库，第一反应是搭 RAG，切片、Embedding、向量数据库、rerank、召回。
事实上，在26年8月的当下，RAG已经过时了。skill的reference才是如今的版本答案。

RAG 在做什么？
RAG 的全称是 Retrieval-Augmented Generation，中文译为检索增强生成。
它先处理资料，把文档切成几百 Token 大小的片段，通过 Embedding 模型把每个片段变成一组向量，随后存入向量数据库。用户提问时，问题也会被转成向量。系统找出语义上最接近的几个片段，把它们塞进模型的上下文，最后生成答案。
但，文档一旦被切片，原有的章节、前后条件、引用关系就可能丢失/失真。
query的向量+语义检索也不一定就满足业务需求。用户问“退货政策”，系统可能同时取回淘宝、京东和亚马逊的规则。某个产品编号、错误码或函数名，也可能因为语义信息很少而被向量检索漏掉。

Skill 里的 Reference 在做什么
Skill 里的 references 走了另一条路。文档保持为普通文件，目录名、文件名、章节和前后关系都还在。SKILL.md 告诉 Agent 什么情况该读哪类资料，Agent 再按需打开。
Anthropic 在 「Agent Skills 设计说明」中把这个机制称为渐进式披露。Agent 启动时先看到 Skill 的 name 和 description。
任务命中后，它再读 SKILL.md。遇到具体问题时，Agent 可以先看目录，根据文件名判断，用 Glob 找文件，用 Grep 搜精确词，再打开命中的章节。前一次查找的结果会改变下一次查找的方向。整个过程没有向量化，和RAG向量库返回的 Top-K 片段有本质差别。

两者的区别？
第一个区别是处理时机。
RAG 在query前，先做资料的切片、向量化和索引。Reference 则是把资料放在文件系统中，Agent 遇到问题后再决定查什么、读多少、下一步去哪里。

第二个区别是基本单位。
RAG 的基本单位是chunking片段，召回时容易切断前后联系。Reference 的基本单位可以是保留完整语义的一份文件、一个章节、一个表格、一段脚本。

第三个区别是谁在做判断。
RAG 的初筛由检索算法完成，Agent 通常只看到筛选后的内容。Reference 模式里，Agent 能看到路径、文件名和邻近文件，可以基于当前任务渐进式地按需检索。

第四个区别是知识库是否方便实时更新。
RAG里文档如果要更新，需要重新走一遍切片，embedding，进向量数据库，调参等流程，很繁琐费劲。Reference 本身就是维护文件夹、文件，Git直接记录，实时的维护和更新非常方便，类似于热插拔。

Claude Code 没有做向量化！
用户问「这个项目的登录是怎么做的」时，Claude Code不是什么向量库找回相似片段，事实上，它先看项目结构，用 Glob 和 Grep 查找内容，搜索 login、auth、路由和中间件，读取命中文件，沿着 import 和函数调用继续往下找，然后查测试、配置和 Git 历史。每次工具返回的结果，都在帮它决定下一步。
Anthropic 为这套思路给了一个名字，just-in-time context。遇到具体问题时，按需渐进地把必要内容加载进入上下文。本质逻辑就是skill的references。而skill也是Anthropic 原创的，自己和自己闭环了属于是。

为什么以前用RAG
RAG 刚火的时候，模型智能水平低、上下文短，指令遵循、工具调用能力弱，大量文档无法直接交给模型。
而26 年条件变了。上下文窗口更长，模型上有fable 5、gpt 5.6的世界级模型，加上claude code和codex的harness版本答案，又发明了skill这个最佳实践，因而agent的能力已经基本吃掉了，甚至远远超过以前得配合RAG才能做的效果。

RAG 留在什么地方？
有几类任务，RAG 仍然很合适。
第一类是数量量级真的很大。几百万工单、邮件、合同、研报和客服记录。
第二类是问题很模糊。用户只记得大概意思，语义检索可以快速给出候选集。
第三类是对延迟和并发要求高。比如在线客服每秒处理大量实时请求，时延必须低。
第四类是知识本来就在外部系统，无法迁移的。例如工单平台、数据库、邮箱和企业文档中心。

这些场景里，适合把 RAG 放在 Agent 外面，封装成一个 MCP，按需调用。

Skill写清什么时候需要外部检索，怎么查询，返回哪些字段。MCP对外提供 search_knowledge等工具，后台完成混合检索和重排后给到agent做参考。

最后，推荐一个让agent执行的，经典的三层知识库检索方式：

第一层用 SKILL.md 和目录结构引导查阅，第二层用 Glob、Grep 或其他本地文本搜索精确定位。内部资料不够时，第三层才通过 MCP 调用外部检索系统。

这种多管齐下的方式，能极大提升找到有效资料的可能性。即使用户的问题描述不够精确，即使知识库中同一个概念有多种表述方式，AI也能通过这种分层、智能的查找体系，高效且准确地找到所需信息。
