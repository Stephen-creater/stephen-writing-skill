# 概念与方法论拆解

## 适用

解释一个概念、岗位、工作方式或商业模型，并给出可执行的实践框架。

## 写法

- 标题是完整判断时，可以零开场直接进入第一节证据。只有标题围绕陌生概念，且不先定义就无法理解后文时，才先用一句话定义。
- 技术概念多时，选择一个读者熟悉的过程作为主类比，并在全文保持一致。
- 面向小白时先说明最少必要名词各自扮演的角色，再用一次完整过程把它们串起来。不要默认读者看过原材料里的公式、图片或动画。
- 每个术语先解释机制，再说它对应的大白话区别。
- 用“与传统做法有什么不同”建立边界，避免只换名词。
- 拆成有顺序的实践步骤，每个步骤回答目的、动作和可观察结果。
- 选择一个贯穿案例，不用多个半句案例堆满全文。
- 方法之后讲能力要求、失败方式和判断标准。
- 重要区别用具体研究或对比结果支撑，随后再压缩成“上限与下限”这类对照。
- 映射到人的学习时，给出输入、反馈、演练和奖励信号等可执行动作。
- 结尾回到业务结果和可复用资产，不把工具当目的。
- 定义、差异和结论各说一次。案例已经证明差异时，不再追加同义总结。
- 标题先确定终点，再决定保留哪些概念。标题从“理解涌现有什么价值”改成“为什么需要世界模型”后，阈值感知、iPhone、泛化细节和商业建议等支线应整节删除。
- 同一主题下的相邻概念，如果回答了另一个读者问题，仍然属于支线。标题讲「模型越聪明，AI 产品越要做减法」时，只保留「为什么能删 → 如何通过失败加回 → Prompt 如何转向验证」，Product Overhang 的创业机会整节删除。
- 概念文的章节必须形成因果链，不按原材料目录缩写。参考链路：`智能涌现 → 知识是压缩算法 → AI 自行寻找压缩算法 → 语言知识存在边界 → 需要世界模型`。
- 优先使用“最少概念 → 朴素计算 → 找出重复 → 引入缓存 → 从单次扩展到跨请求 → 使用陷阱”的递进线。案例必须明确列出每次输入、输出、重复前缀和新增内容。
- 如果完整案例已经讲清概念价值，删除不改变定义与边界的应用场景整节。短技术科普可以在结尾用一句话压缩两个概念的最终区别，但不要在开头先说一遍、结尾再重复。
- 行业观点文开头用一句核心冲突切入，小标题直接交付判断。面向小白时，删除依赖编程背景的案例，不为保留案例补充 Jira、GitHub 等工具解释。
- 企业 AI 落地文章可以先用分布或失败现象说明问题，再提炼成「先锋 → 共享 → 嵌入」的递进路径。先锋负责找到高价值场景并做出成果，共享机制把个人方法变成组织资产，流程嵌入覆盖不愿主动学习工具的大多数员工。
- 自有企业项目案例只保留能证明当前路径的事实，删掉人物包装、服务介绍和销售入口。
- 面向业务从业者的行业观点文，可以从通用产品格局切到业务层缺口，再回答哪类人更有优势以及需要补什么能力。标题不要求解释概念时，删除定义、四要素和产品代际等知识支线。
- 千字短文可以不设小标题，但必须保持「竞争格局 → 机会缺口 → 受益人群 → 行动方法」的连续推进。
- 宏观趋势观点文先找两个真正不可替代的问题。例如「个性化新需求从哪里来 → 无法自产自销的需求怎样被满足」。知识门槛、时间成本、供给规模、平台分发和质量争议只是中间解释时，可以由小标题或一句话承接，不分别建章。
- 一个具体场景已经证明个人趣味会创造新需求时，删除同类作品清单、第二个生活案例和销售对话。案例的主体不是作者身份时，可以从「我为什么做」压成「为什么还要自己做」，让判断直接落在读者身上。
- 趋势文结尾优先寻找旧机制与新机制的对照。已经从「搜索或推荐已有产品」推进到「私人定制产品」时，市场形状已经闭合，不再补平台模式、价格战、质量评价和再次表态。

## 避免

- 保留访谈、会议或逐字稿痕迹。
- 把普通常识包装成新方法论。
- 只写步骤，不写成功与失败的判断方式。
- 在开头、分析段和结尾反复申明同一主张或适用边界。
