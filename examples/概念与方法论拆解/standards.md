# 概念与方法论拆解

## 适用

解释一个概念、岗位、工作方式或商业模型，并给出可执行的实践框架。

## 写法

- 开头提出读者真正会问的问题，随后立即给出一句话定义。
- 技术概念多时，选择一个读者熟悉的过程作为主类比，并在全文保持一致。
- 面向小白时先说明最少必要名词各自扮演的角色，再用一次完整过程把它们串起来。不要默认读者看过原材料里的公式、图片或动画。
- 每个术语先解释机制，再说它对应的大白话区别。
- 用“与传统做法有什么不同”建立边界，避免只换名词。
- 拆成有顺序的实践步骤，每个步骤回答目的、动作和可观察结果。
- 选择一个贯穿案例，不用多个半句案例堆满全文。
- 方法之后讲能力要求、失败方式和判断标准。
- 重要区别用具体研究或对比结果支撑，随后再压缩成“上限与下限”这类对照。
- 映射到人的学习时，给出输入、反馈、演练和奖励信号等可执行动作。
- 结尾回到业务结果和可复用资产，不把工具当目的。
- 定义、差异和结论各说一次。案例已经证明差异时，不再追加同义总结。
- 标题先确定终点，再决定保留哪些概念。标题从“理解涌现有什么价值”改成“为什么需要世界模型”后，阈值感知、iPhone、泛化细节和商业建议等支线应整节删除。
- 概念文的章节必须形成因果链，不按原材料目录缩写。参考链路：`智能涌现 → 知识是压缩算法 → AI 自行寻找压缩算法 → 语言知识存在边界 → 需要世界模型`。
- 优先使用“最少概念 → 朴素计算 → 找出重复 → 引入缓存 → 从单次扩展到跨请求 → 使用陷阱”的递进线。案例必须明确列出每次输入、输出、重复前缀和新增内容。
- 如果完整案例已经讲清概念价值，删除不改变定义与边界的应用场景整节。短技术科普可以在结尾用一句话压缩两个概念的最终区别，但不要在开头先说一遍、结尾再重复。

## 避免

- 保留访谈、会议或逐字稿痕迹。
- 把普通常识包装成新方法论。
- 只写步骤，不写成功与失败的判断方式。
- 在开头、分析段和结尾反复申明同一主张或适用边界。
