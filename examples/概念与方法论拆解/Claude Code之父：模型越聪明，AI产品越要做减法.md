# Claude Code之父：模型越聪明，AI产品越要做减法

## 一、Claude Opus 5 已经不需要大量脚手架

Boris ，也就是Claude Code之父，说每次有新模型发布，团队都会删除一大批 system prompt。他们一直在调整工具集，也一直在修改工具所使用的 prompts。

为什么能删？system prompt 里很多内容，原本是在纠正模型的一些行为，但现在 Opus 5 自己就能做到了，过去用来补齐能力的提示词，反而会占用上下文和影响模型性能，所以新版Claude Code 删除了 80% 的 system prompt。

## 二、先删除，再根据失败加回来

AI 产品需要不断做减法。每一代模型发布后，都应该重新审视 Prompts、Skills、Hooks 和工具，只有当模型反复在同一个地方失败时，才把相应的约束加回来。

他们把这个过程叫作 ablation（消融实验）。具体来说，就是把整个 system prompt 删除，然后再逐行把它加回来，以判断每一行单独产生的影响。Ablation 本质上是一种 Eval（评测），只不过你通过删除东西来判断它所产生的影响。

第一步是删除，下一步是直接使用，测试效果。你不应该去猜模型需要什么prompt，因为实际上无法准确预测。

只有当发现它反复在同一个地方出问题时，才应该把相应的指令加回来。

## 三、PE的重点变成验证结果

Prompt Engineering 的重点正在从「教模型怎么做」转向「让模型验证结果」。好的任务只需要交代目标、约束与完成标准，再提供测试、截图或运行环境，让模型能够判断自己是否做对。

一个非常常见的错误是，在使用 Claude时，给它过于具体的指令。他们会说：我希望你完成这个任务，但我要你按照这种方式来做，你必须先做第一步，然后第二步、第三步……

对现代模型来说，这种使用方式已经过时。应该把任务描述得稍微高层一些，说明任务是什么，说明 Guardrails（约束边界），说明 Exit Criteria（完成条件），然后就放手让模型去做，过一会儿再回来看看结果。

Boris 举了个例子，让claude code把跨平台桌面应用重写成 Mac 原生版：「现在我要你做的是，把这个 Electron 应用重写成 Swift。我希望你先在 Mac 虚拟机里运行 Electron 应用，给它截图，然后逐个像素地进行观察，把它和 Swift 版本进行比较。在完成之前不要停下来。」这个任务已经连续运行了两周以上。

对于越来越多的软件开发任务而言，编程正在接近被ai解决。真正拉开builders差距的，将是提出问题、设计产品、理解用户、判断商业价值，以及敢于重新测试那些过去被认为「不可能」的事情。
