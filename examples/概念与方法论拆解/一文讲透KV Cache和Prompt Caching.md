# 一文讲透KV Cache和Prompt Caching

## 一、KV Cache 是什么？

先简单理解下几个名词概念。Attention 理解为 LLM 输出回答时需要进行的一种计算，每输出一个 Token 都要计算一遍。Q 是当前已经进入模型、正在被处理的 Token 所提出的查询，需要结合前面的 K 和 V，才能帮助模型输出下一个 Token。K 可以理解为前面每个 Token 的索引，V 是索引背后的具体内容。

当我们输入一段提示词，LLM 在实际输出回答的时候，会先计算提示词的 Attention，然后吐出第一个 Token，接着把第一个 Token 拼到回答序列的末尾，再对整个新序列重新计算一遍 Attention，得到下一个 Token。

假设要生成 10 个 Token，朴素实现的过程是：第 1 步输入 P（Prompt），算 Attention，输出 Token 1；第 2 步输入 P+Token 1，算 Attention，输出 Token 2；第 3 步再输入 P+Token 1+Token 2，然后继续计算。

注意，第 2 步中，Prompt 部分对应的 K、V，和第 1 步计算出的结果完全一样，因为输入和模型参数都没变。每一步重算前缀，是纯粹的浪费。

这时候就需要 KV Cache 了。核心一句话：把前面所有 Token 的 K 和 V 缓存起来，每次新 Token 只算自己的，然后跟前面的缓存拼起来计算 Attention，减少重复浪费。

## 二、Prompt Caching 又是什么？

到这里，KV Cache 解决的是「单次生成内」的重复计算问题。但还有一个浪费：不同请求之间的重复计算。

假设你问 AI「明天北京天气怎么样」，后台其实发生了两次模型调用。

第一次调用：输入是「System Prompt + 天气工具说明 + 用户问题」，模型输出一条工具调用指令：查询北京明天的天气。

后台执行工具，得到「北京明天晴，最高温度 28℃」，然后发起第二次模型调用。

第二次调用：输入是「System Prompt + 天气工具说明 + 用户问题 + 第一次输出的工具调用指令 + 天气工具返回的结果」，模型才输出最终答案。

为什么第二次调用还要把前面的内容全部再发一遍？因为模型本身没有状态，我们需要把上一次的聊天记录一起发给它，它才知道历史上说了些什么。

比较两次输入就能发现，第二次调用完整重复了第一次调用中的「System Prompt + 天气工具说明 + 用户问题」。按照普通的计算方式，这段前缀虽然刚刚计算过，第二次仍然要重新计算一遍 K、V。

Prompt Caching 的核心思路就是：把 KV Cache 的复用范围从「单次推理内」扩展到「不同请求之间」。第二次调用发现开头完全相同，就直接复用这段公共前缀的 K、V，只计算后面新增的工具调用指令和天气结果。

## 三、Prompt Caching 踩坑的注意事项

第一个常见陷阱：前缀必须完全一致才能命中缓存，哪怕多了一个空格、改了一个字符，就可能缓存 Miss、重新计算。

第二个常见陷阱：缓存的时效性。Claude 的缓存默认有效期是 5 分钟，如果超过 5 分钟没有命中过，缓存就会失效。

所以防止踩坑的核心要点是：固定内容在前，动态内容在后。

以上，总结来说，KV Cache 是「单次推理内」的优化，同一次生成的不同 Token 之间复用；Prompt Caching 是「跨请求」的优化，不同请求之间复用相同前缀。本质上是同一个缓存思路在两个时间尺度上的应用。
