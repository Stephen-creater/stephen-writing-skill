# 从 Stephen 的定稿里学

只在 Stephen 给出定稿、逐条提意见，或者要求改 Skill 时读。目的是让下一篇初稿更接近他会发的样子，不是把每次修改都变成一条新规定。

## 步骤

1. **找齐三样东西**：Agent 的初稿（`<日课创作>/work/`），Stephen 的发布版（`<日课创作>/已发布文章/`，先运行 `python3 scripts/sync_published.py` 同步；或者他直接贴回来的全文），以及他说过的原话。
2. **先看他实际改了什么**：删了哪几节、哪几段，加了什么，挪了什么，标题怎么变，「我」「你」怎么变，结尾怎么收。先记事实，不急着总结原则。
3. **判断要不要进规则**。只有两种情况写进写作指南：
   - Stephen 明说「以后都这样」；
   - 至少两篇不同的文章里出现了同一种修改。
   其余情况只把定稿当范文用，规则不动。一次修改只能说明「这篇这样改更好」。
4. **改规则的写法**：
   - 先在 [写作指南](writing.md) 里找管这件事的那一条，有就改那一条，不新增；同一件事只写一处。
   - 写清楚做法、为什么、一个例子。
   - 想一个反例：这条规则会不会误伤别的文章？会就把适用范围写窄。比如「小标题要下判断」会误伤产品速览，正确的说法是「小标题为读者要做的事服务」。
   - 例子只能用评测开发集里的文章，不能用留出集的（见 [评测](evaluation.md)），否则留出集就测不出规则是不是只记住了旧文章。
5. **跑评测**：按 [评测](evaluation.md) 跑新旧版本对比。没通过就不提交，找出输在哪几篇，改了再测。
6. **范文**：新定稿要放进范文库时，放进对应分类，并在那一类的 standards.md 更新推荐。范文会同步到公开 GitHub，放之前确认 Stephen 同意公开这篇。

## 不要这样改

- 把一篇文章的专有名词、章节数量写成所有文章的模板。
- 因为一次结尾不够好，就要求篇篇都要有惊喜的结尾。
- 因为一次第一人称不够，就要求每段都出现「我」。
- 在 SKILL.md、写作指南、审稿指南、分类说明里重复写同一句规则。
