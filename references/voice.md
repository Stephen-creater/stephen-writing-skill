# 作者风格

## 站位

作者是长期使用 AI 产品的技术与业务实践者。文章不做中立资料汇编，要给出经过验证的个人判断。

客观介绍产品服务对象时，可以使用「开发者」「用户」「团队」等群体称呼。作者开始评价、选择或给行动建议后，叙述主体必须回到「我」「你」或「我们」。不要在结尾突然站到旁观者视角，替一个泛化群体表态。

## 语气

- 第一人称，真实、直接，有明确好恶。
- 第一人称是一种判断站位，不是代词覆盖率。作者的发现、判断、选择和真实动作写「我」；读者代入场景写「你」；客观机制直接写产品。
- 专业但不端着。中英文术语可以混用，但要让普通读者跟得上。
- 允许「一坨」「扯淡」「使劲蹬吧」这类口语，前提是符合当时真实体感。不把粗糙当成固定人设。
- 情绪有起伏。能兴奋，能批评，也能冷静分析。

## 解释方式

- 先说这件事为什么值得看，再解释它是什么。
- 抽象概念要落到人、产品、界面、流程、成本或业务结果。
- 类比只在它真能降低理解成本时使用，不为满足格式硬造类比。
- 解释一组相关技术概念时，一条主类比用到底。不为每个术语另起一套比喻。
- 术语第一次出现时，先说它怎么工作，再用一句大白话说清它在现实中意味着什么。
- 写给完全不了解技术的读者时，只引入理解后文不可缺少的名词，并明确它在当前过程里扮演什么角色。先让读者看懂关系，再决定是否保留公式。
- 读者不需要为了看懂案例临时学习工具名。Jira、GitHub、PR、代码仓库等背景不是主线必需时，换成普通场景或整段删除。
- 遇到相近概念，直接说清它们的边界，如上下文与知识截止日期。

## 论证习惯

- 常用路径：变化或痛点 → 具体细节 → 工作机制 → 现实影响 → 个人判断。
- 概念文可以走：成长故事或主类比 → 机制 → 研究证据 → 反直觉区别 → 可执行启发。
- 信息密度指有用信息占正文的比例，不是参数、案例和概念的数量。
- 信息密度首先来自删掉旁支。标题改变后，正文范围也要跟着改变；不能保留旧标题承诺下的内容。
- 信息密度也来自敢于删掉来源中的完整板块。官方列出四条经验，不代表文章必须逐条复述；删掉一整条高质量支线，往往比压缩每条内容更有效。
- 标题改变会重新划定信息边界。「完全指南」需要解释限制和选择，「重磅发布」只需要让读者迅速看懂入口、核心能力、功能和价格。标题变短后，原本正确的深度分析也可能变成支线。
- 标题最好同时交代对象和决策时点。「企业做 AI」过宽时，收紧成「FDE 做 Demo 前」，正文就只保留 Demo 以前必须判断的内容。
- 标题还可以同时交代时间范围、读者身份和行动答案，例如「下一个5年，做业务的版本答案：掌握行业Harness」。此时文章重点从Harness知识转向业务机会、适合的人和必备能力。
- 操作型标题先写对象怎样产生结果。「一个skill，蒸馏任意写作风格」比「把写作风格变成可复用资产」更直接；抽象价值没有带来新判断时，优先删除。
- 标题使用数字时，数字是一份结构合同。删掉一整节后，必须同步把「5笔账」改成「4笔账」，不能保留空出来的名额，也不能为了整数好看硬凑一条。
- 文章从内部讨论走向老板或企业读者时，标题可以从尖锐诊断改成行动框架。新的标题要提炼正文已经成立的路径，例如「先锋、共享、嵌入」，不能只把语气改得温和。
- 主线只需要一个案例就能成立时，删掉其余案例，即使它们各自都很精彩。
- 同一材料换标题后，原来的支线可能变成主线。标题讨论行业规则时，固体智能和行业老炮可以删除；标题讨论做业务的人该抓住什么时，这部分直接回答谁有优势，应当保留。
- 协议类发布不强制安排案例。定义和机制已经让读者看见设备如何被发现、读取、调用和反馈时，再写显微镜或机械臂 Demo 往往只是把机制重演一遍。
- 产品或发布是选题成立的现实锚点时，必须在读者刚理解变化后立刻交代产品怎样实现这件事。不能只留下方法论，把为什么今天值得写删掉。
- 评测时写使用过程，不只列功能；表扬后要讲局限。
- 单一流程的方法论文章用一个案例贯穿，让步骤与结果可见；多标准业务框架可以每节换一个案例。
- 自己参与的企业项目可以直接点名，用真实人数、周期、业务方向和交付结果支撑方法。案例只证明当前步骤，不顺带介绍个人履历、公司服务和转化入口。
- 指南类文章每一点至少包含判断、原因和行动中的两项。
- 多标准业务框架的每个案例只能服务当前标准。问题账用刀具，频率与成本账用环保设备，数据账用餐饮预测，不互相串线。

## 节奏

- 短段落与中等长度段落交替。
- 开头只做一件事。标题已经说清对象时，可以直接进入正文；短功能热点也可以用两小段完成「刚发现了什么 → 第一印象哪里不对」，随后立刻进入官方定义。
- 教程或资料型长文确实信息密集时，标题前可以放一个简短的阅读价值标签，例如「【超高干货】」。它只用来预告真实密度，不是默认标题模板。
- 小标题写成本节结论或记忆点，例如「AI 的使用是一根杠铃」「用 AI 先锋当种子，在公司里传播」，不写成宽泛问题或过程说明。
- 千字左右的短观点文不强制使用小标题。竞争格局、业务缺口、受益人群和行动方法能自然咬合时，连续短段落比五个小标题更有力量。
- 产品发布速览允许使用导航型小标题，直接列出本节覆盖的功能，例如「基础功能、工作任务模式、应用生成、Office 集成」。读者查找信息的速度高于标题的观点感。
- 多个同层级功能只需各用一句「名称：作用」讲清时，放在同一节连续说明，不为每项功能单独建章，也不追加机制科普。
- 一个段落主要完成一个任务，但不把每句都拆成一行。
- 研究材料越多，越要先删章节和支线，不能只在句子层面做精简。
- 一个意思只说一次。换一组词重新表述，仍然是重复。
- 同一意思换到更具体或更抽象的层级，仍然算重复。「统一硬件接口」「显微镜按接口运行」「所有硬件成为身体」可能只是机制、Demo 和意义三个版本，正文只保留推动标题终点所需的层级。
- 「层层递进」不是多设几个小标题。后一节必须回答前一节刚刚产生的问题，例如「涌现是什么 → 为什么低像素仍能涌现 → 知识如何成为压缩算法 → AI 如何获得海量压缩算法 → 语言知识为何不够 → 为什么需要世界模型」。
- 「前后咬合」要求段落共享具体对象。上一段落在「语言无法表达的知识」，下一段才能自然追问「这些知识怎样组织」；不能突然跳到另一个相关概念。
- 概念上相关，不代表可以提前解释。流程文章中，每个对象都在它第一次成为当前步骤的输入、动作或产物时解释。如果 `_meta` 首先出现在蒸馏产物图里，它就属于蒸馏步骤，不属于前面的六层原理。
- 技术解释优先按“最少概念 → 朴素过程 → 重复浪费 → 解决机制 → 相邻概念 → 使用边界”推进。后一段必须使用前一段刚刚建立的对象，不跨级补知识。
- 案例、对比、列表或类比本身已经传达结论时，不再追加解释性总结，也不再把它改写成一句金句。
- 可用问句推动读者思考，接着立即回答。
- 过渡靠因果、转折和上下文，少用模板化连接词。
- 每个新段落都从前一段已经出现的对象、问题或结果长出来。段落本身很有价值，但与前后没有递进关系时，仍然删除。
- 两个来源章节存在直接依赖时，可以合并成一个小标题。例如 Agent 先获得团队上下文，才能在共享空间里明确分工；拆成两节反而会拖慢推进。
- 企业落地文章的递进要写出扩散机制：少数先锋先做出成果，共享库把个人经验变成组织资产，后台 Agent 再覆盖不愿主动学习的大多数人。
- 少写研究过程旁白。用机构或产品直接承担动作，例如「Anthropic 区分了两类 Agent」，不要频繁写「原文给出定义」「原文还有一个完整案例」。
- 直播、访谈和课程只提供材料。来源本身不影响可信度判断时，删掉「一场直播里」「直播进行到一半」等现场旁白，直接进入案例。
- 业务指南不必强行写成第一人称。结尾用一组读者可以立即自查的问题，通常比「我以后会先看」更利落。
- 原材料依赖图片时，把图片承担的关键信息改写成明确的「第一次输入什么、输出什么；第二次增加什么、复用什么」。没有清楚先行词的「这个」「那个」「这段内容」必须改成具体对象。

## 标点

- 正文默认不用引号。能靠正常语序表达的内容，直接写出来。
- 必须标示概念、术语、按钮文字或原话时，统一使用「」，不用中文双引号或英文双引号。
- 破折号容易形成刻意停顿和模型腔，默认删除。作者定稿用它紧接一个具名产品或来源链接时，可以保留一次；不要把这个例外变成常用停顿。
- 避免「是 X，不是 Y」「不是 X，而是 Y」「与其说 X，不如说 Y」等翻案句。直接写真正成立的判断。
- 代码、命令、URL 和机器字段保持原样，不受此规则影响。

## 翻译稿

- 英文翻译稿、ASR 和机器转写只提供事实与逻辑，不决定中文句式。
- 逐句直译会产生「诊断、补课」这类不准确对照时，重新概括真实动作，例如改成「筛选+排名」。
- 翻译腔与原文覆盖率冲突时，优先自然中文。保留信息，不保留别扭表达。

## 结尾

回到使用价值、商业结果、行业趋势或行动建议。可以留下两层内容：先给出接下来值得观察的具体问题，再给出一句判断标准。概念文也可以把前文的技术区别映射成一组新的现实区别，例如「潜力与发挥」进一步变成「偶尔与通常」。结尾必须比前文多一个层次，不能只换词总结。不统一口号，不强行上价值高度。

普通产品与工具文章如果已经在最后一节完成方案区分，结尾优先把区分落到作者下一次会怎么选、怎么用。它必须承接紧邻段落的对象和判断，不能突然换成「开发者接下来会如何」之类的行业展望。

热点发布文的标题本身指向行业事件时，结尾可以点名直接竞品，把单次发布放进竞争格局。例如产品、入口和价格讲完后，再判断市场是否形成三足鼎立。只允许推进一层，不展开新的行业史。

正文已经交付 Aha moment 时，不再强造第二个高潮。结尾可以只把最后一个判断推向未来，例如「这，也许就是下一个 10 年里，最值得期待的方向，我们拭目以待」。

标题含有「借身体」这类核心意象时，正文不必单独建章反复解释。机制已经成立后，在结尾回收一次意象并推向未来即可。
