# 反馈学习协议

只有在用户给出定稿、逐条审核或明确要求优化 Skill 时读取。目标是更新判断系统，不是把每次修改变成一条新禁令。

## 核心原则

一次修改只能证明「在这个任务合同下，这样改更好」。要成为跨题材规则，还需要解释它解决了什么根因、在哪些场景成立、在哪些场景不成立。

## 每次反馈的处理流程

### 1. 还原差异

同时保留模型稿、用户定稿和用户原话。先记录可观察变化：删了哪一节、移动了什么、标题如何变化、代词如何变化、结尾如何收口。不要一开始就发明抽象原则。

### 2. 找根因

把表面修改追到一种编辑问题：文章合同、读者门槛、主路径、语义重复、对象顺序、证据强度、个人声音或交付媒介。一次反馈可能只需要更新一个根因，不为每个删句建立规则。

### 3. 判定作用域

- `全局硬边界`：真实性、授权、不伪造等。
- `全局偏好`：高信息密度、自然中文、少引号等。
- `任务条件`：只有标题、读者、媒介或材料满足某条件才启用。
- `单篇选择`：只写进案例，不进入规则。

为新原则找一个反例。若规则无法容纳反例，就缩小作用域。例如「小标题必须下判断」会误伤产品导航；正确抽象是「小标题必须服务当前读者任务」。

### 4. 更新最高层

先检查现有规则是否表达不清、优先级错误或彼此冲突。优先替换、合并和删旧规则，不在多个文件追加同义句。

- 跨题材取舍写进 `editorial_decisions.md`。
- 稳定的个人表达偏好写进 `voice.md`。
- 最终是否过关写进 `check_standards.md`。
- 题材独有差异写进对应 `standards.md`。
- 单篇技巧只留在案例。

同一原则只设一个权威位置，其他文件只链接或给题材差异。

### 5. 回归验证

至少用两个不同题材的既有定稿验证新规则：一个支持它，一个可能构成反例。检查新规则是否会误删必要内容、强迫固定结构或制造代词和篇幅过拟合。

## 三个会话沉淀出的核心认知

| 反馈簇 | 反复出现的修改 | 最终抽象 | 反例或边界 |
|---|---|---|---|
| 重复与废话 | 删除换词复述、段后总结、同类案例 | 信息密度看有效增量，删除测试按问题到句子执行 | 必要阶段结论若改变下一段方向可以保留 |
| 层层递进 | KV Cache、智能涌现等文章重排因果 | 后一段使用前一段建立的对象并回答其问题 | 决策清单可以并列，但共同决定同一行动 |
| 用户视角 | 删除 Jira 背景，补图片缺失信息，禁止空指代 | 降低与主线无关的门槛，保留必要机制 | 专业读者本来掌握的术语不必统一解释 |
| 第一人称 | Computer History 多次重写 | 第一人称是作者承担发现和判断 | 客观机制和适用群体仍由真实主体承担 |
| 开头 | AI 普及、短热点大幅缩短热身 | 开头只建立核心冲突，标题已完成时可零开场 | 陌生对象需要最短定义时保留 |
| 小标题 | 改成「一根杠铃」，速览保留功能导航 | 小标题服务读者任务，可以是判断或导航 | 不统一强制观点型标题 |
| 整节删减 | 删除 MHS Demo、Product Overhang、趋势中间推演 | 与主题相关不等于服务标题，整节删除优先 | 新变量、反例、量化结果或边界不可删 |
| 对象顺序 | `_meta` 提前出现造成混乱 | 对象按读者实际遇到的顺序解释 | 概览可先点名，详细解释放对应步骤 |
| 来源整合 | 一篇为主，其他补独有内容，删除广告与旁白 | 来源是材料库，不是正文目录 | 用户要求完整转载时遵守原文任务 |
| 覆盖率 | 40% 到 85% 随任务变化 | 覆盖率服从本次要求，是保真指标 | 事实、自然中文和完整指代不能牺牲 |
| 结尾 | 智能涌现要 Aha，MHS 只需期待，趋势文两节闭合 | 结尾只补正文最后缺的一步 | 正文已完成 Aha 时短收或结束 |
| 中文质感 | 禁双引号、少破折号、反感翻案句和翻译腔 | 直接说成立的判断，减少模型化修辞 | 代码、URL、必要原话不机械改写 |
| 证据边界 | 强比例、官方主张、案例强度 | 判断强度不超过证据，案例不继承事实 | 用户确认亲历可作第一手材料但不外推 |

## 禁止的补丁式更新

- 不把案例中的专有名词和章节数量写成全局模板。
- 不因一次结尾不够精彩就要求所有文章结尾必须 Aha。
- 不因一次第一人称不足就要求每段出现「我」。
- 不因一次导航标题有效就取消观点型标题。
- 不在入口、声音、检查表和分类标准重复同一句规则。
- 不保留已经被更高阶原则覆盖的旧例外。

## 更新记录格式

```text
观察到的修改：
根因：
抽象原则：
作用域：
反例：
替换或删除的旧规则：
回归案例：
```

用户确认定稿后再更新案例。规则更新完成后运行结构校验、链接检查和样式检查，并按项目 Git 纪律提交与同步。

如需把确认稿另存到父项目成稿目录，使用：

```bash
python3 stephen-writing-skill/scripts/save_draft.py "文章标题" "待存档文件.md"
```
