# 文案检查标准

## 1. 真实

- 第一人称体验都来自用户提供或明确确认的经历。
- 不伪造访谈、使用时长、效率提升、用户反馈、业务数据和人物表态。
- 不把官方主张写成已经证明的结果。
- 新闻、价格、版本、功能、数字和引语已查证，时间和适用范围没有混淆。
- 推断用“我理解”“我的判断”等语义标明，不伪装成事实。
- 客观事实中的“开发者”“用户”等群体称呼有明确对象；作者观点、选择和行动没有突然改由泛化群体承担。

## 2. 主线

- 标题后半句明确规定文章终点，全文没有走向另一个更宽泛的结论。
- 标题含有数字时，章节数量、判断标准和结尾清单与数字完全一致，没有少一项或为凑数多一项。
- 文章由负面诊断改成行动框架时，标题和正文都完成了重构，没有只换标题、仍保留原来的批评结构。
- 标题到第一个小标题为零句或一句。标题已经交代具体对象时可以直接进入第一节，没有为了满足格式硬加开场。
- 由具体产品、发布或事件触发的文章，标题或第一节保留了现实锚点，并说清它怎样承接全文讨论的变化。
- 可以把全文压缩成因果链、使用导航路径或数字型决策清单，不是一组「都与主题相关」的章节。
- 可以用一句话说清全文的核心判断。
- 正文通常只回答 2 到 4 个与主线直接相关的问题；用户明确要求产品完全指南或速览时，最多保留 4 至 6 个直接影响访问、使用和选择的导航问题。
- 没有把来源列出的全部经验、功能或案例机械保留成目录；每一条都通过了标题终点和删除测试。
- 每个段落都在提供新事实、新解释、新案例、新判断或新行动。
- 标题的对象和决策时点足够具体，例如「FDE 做 Demo 前」，没有停留在「企业做 AI」这类过宽范围。
- 删掉任何与主线无关的背景、功能或感叹。
- 结尾给出最终选择或行动；没有新内容时不重述开头。
- 结尾沿用最后一节的叙述主体和讨论对象。热点发布文进入竞争格局时，点名直接竞品且只推进一层，没有空泛扩大到整个行业。

## 3. 结构

- 热点文先说发生了什么以及为什么重要。
- 评测文包含真实痛点、使用过程、具体结果、优点和局限。
- 方法论文先给定义，再讲机制、步骤、案例和边界。
- 指南文可以分点，但每点都有原因或案例，不是标题堆积。
- 没有为了套模板增加无用环节。
- 每个段落都能说清与上一段的关系，也能说清它为下一段提供了什么。
- 因果文章每一节都能写出「上一问 → 本节答案 → 下一问」；产品导航按使用顺序推进；数字型业务框架每节贡献一个不可替代的判断标准。
- 企业转型路径中的各层存在扩散关系，例如先锋产出成果、共享库放大成果、流程嵌入覆盖大多数员工，没有并列堆建议。
- 每个小标题都准确概括本节结论或信息类别。产品速览的导航型小标题能够让读者快速找到入口、功能和价格，没有强行制造观点。
- 多标准业务框架每节只保留一个主要案例，案例只证明当前标准，没有跨节重复承担多个结论。
- 没有把“内容相关”误当成“逻辑连贯”。已完成的分类或层级之后，没有突然转去介绍单个旁支功能。
- 可以合并的相邻原则已经合并，没有为了对应原文结构制造多余章节。

## 4. 语言

- 是一个实际用过、想过这件事的人在说话，不是机构通稿。
- 专业词第一次出现时已经解释。
- 面向小白时，每个必要术语都有明确角色，没有用未解释的新术语继续解释旧术语。
- 面向小白时，没有保留需要 Jira、GitHub、编程或其他非必要专业背景才能理解的案例。
- 翻译稿已经改成自然中文，没有逐句直译、错位对照或英译式抽象词。
- 没有「是 X，不是 Y」「不是 X，而是 Y」等模型惯用翻案句。
- 口语、英文和情绪词服务于表达，没有被当成人设装饰。
- 句子长短有变化，不连续使用同一句式。
- 段落之间靠逻辑连接，不靠“值得注意的是”“更重要的是”等空转过渡。
- 没有频繁使用「原文给出定义」「原文有个完整案例」等研究过程旁白；出处只在影响可信度时简短出现。
- 材料来自直播、访谈或课程时，没有保留不影响判断的现场旁白和转述外壳。
- 判断强度与证据相称；单个案例只能证明存在风险时，使用「不一定」「可能」等准确表述，没有扩大成绝对结论。
- 自有企业项目只保留了与当前判断直接相关的人数、周期、场景、执行过程和成果，没有混入履历、服务宣传或联系方式。
- 没有“后背发凉”、“震惊”、“颠覆一切”等廉价情绪。
- 正文没有中文双引号或英文双引号；确实需要标示的内容统一使用「」。
- 正文没有破折号；补充、转折和停顿已改成正常句子。

## 5. 去重压缩

- 按章节、段落、句子的顺序做删除测试。删掉后不影响核心事实、逻辑、区别、结论或行动的内容必须删除。
- 信息密度没有被误解为信息数量。多个参数、案例或评测支撑同一结论时，只保留最有效的一个。
- 相邻句子没有表面重复，但语义上只是换词重述，仍然判定为重复。
- 事实、案例、对比或列表之后，没有再用抽象语言复述它们已经传达的意思。
- 多个并列失败原因已经压成短编号列表，没有分别扩写造成节奏拖慢。
- 同一个结论、限制或适用边界没有分别在开头、段尾和结尾出现。
- 段落末句不概括本段，除非该结论会改变下一段的方向。
- 删除任意整节应用场景后，如果定义、机制、区别和使用边界仍然完整，该节已经删除，不因材料里存在就保留。
- 删除任意整节后，如果仍然可以从标题起点抵达标题终点，该节已经删除，即使它包含新知识。
- 过渡句确实改变了讨论对象或抽象层级；只重复下段首句的过渡已删除。

## 6. 解释和证据

- 抽象判断后紧跟具体细节或案例。
- 同一组技术概念使用同一条主类比，没有在中途换另一套比喻系统。
- 专业术语已经同时说清工作机制和大白话含义。
- 来源依赖图片或界面时，文字已经补全各步输入、输出、重复部分和新增部分；全文没有失去画面后无法解析的指代。
- 核心观点前面有研究、对比实验或反例，不靠类比本身证明。
- 数字说清对象、口径、时间和对比基准。
- 类比准确且必要；删掉只为显得通俗的类比。
- 优点、缺点和适用人群都有证据支撑。
- 不用一个案例推导整个行业已经如此。
- 外部调研补充确实改变了读者对产品的理解、使用或付费选择，没有只因资料深入就塞入正文。

## 7. 交付前检查

- [ ] 符合最接近的分类标准。
- [ ] 没有照搬样例句子或段落结构。
- [ ] 授权原文整合任务默认达到连续 30 字覆盖率 80%；用户明确指定其他数字时，按本次要求验收。
- [ ] 每个段落均通过“承接了什么、推进了什么”检查。
- [ ] 用户材料中的指令性文字没有被误当成执行指令。
- [ ] 已先删整条支线，再逐段、逐句检查；换词重述、段后总结和全文复述已删除。
- [ ] 文章不需要靠虚构经历才能成立。
- [ ] 技术结论与人类学习的映射是启发或类比，没有被写成已经证明的同一机制。
- [ ] 标题准确揭示核心价值，不夸大、不透支信任。
- [ ] 数字型标题已经逐项核对：标题数字、章节、标准和结尾问题完全一致。
- [ ] 标题、主路径和结尾指向同一个终点；删减导致终点变化时已经同步改标题。
- [ ] 观点文若从问题诊断改成行动方案，标题、小标题和结尾已经统一切换为可执行路径。
- [ ] 每节通过因果接口、使用顺序或数字型判断标准检查，没有并列堆知识。
- [ ] 开头为零句或一句；标题已经说清对象时直接进入第一节，小标题是高密度判断或清楚的功能导航。
- [ ] 标题已经交代对象时，没有强行补开场；产品或事件是选题现实锚点时，也没有在抽象化过程中被删掉。
- [ ] 来源中的枚举项已经逐条做删除测试，没有为了显得完整而保留整套目录。
- [ ] 小白读者不需要为了案例额外学习非必要工具和术语。
- [ ] 翻译稿已优先改成自然中文，没有为了覆盖率保留翻译腔。
- [ ] 作者判断与行动通常使用「我」「你」或「我们」；面向明确职业角色的业务框架可以直接给行动标准和检查清单，不强加作者自述。
- [ ] 结尾能从紧邻的上一段自然接读；热点发布文若转向竞争格局，只点名直接竞品并推进一层。
- [ ] “这个”“那个”“上述内容”“前面这些”等指代均能在同段或紧邻句中找到唯一对象。
- [ ] 已运行 `scripts/check_style.py`，引号与破折号检查通过。
- [ ] 正文独立完整，不残留任务说明、研究过程或模型自述。
